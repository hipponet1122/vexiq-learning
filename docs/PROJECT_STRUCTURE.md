# Project Directory Structure & Organization Rules

> 正體中文版見 [`docs/zh-TW/PROJECT_STRUCTURE.md`](zh-TW/PROJECT_STRUCTURE.md).

This document defines where every file belongs in the repository so the project stays clean and predictable as new features are added.

## 1. Root Directory Policy

Keep the repository root minimal. **Only standard project metadata, Docker/runtime entrypoints, and top-level directories belong in the root:**

| File / Directory | Purpose | Version Controlled? |
| :--- | :--- | :--- |
| `README.md`, `CHANGELOG.md`, `LICENSE`, `VERSION` | Standard repository metadata & release history | Yes |
| `server.py`, `requirements.txt` | FastAPI backend entrypoint & Python dependencies | Yes |
| `Dockerfile`, `docker-compose.yml`, `docker-entrypoint.sh`, `.dockerignore` | Container build & runtime configuration | Yes |
| `.gitignore` | Git ignore rules | Yes |
| `web/` | Frontend application (plain HTML/CSS/JS, no build step) | Yes |
| `docs/` | Public documentation (English in `docs/`, 正體中文 in `docs/zh-TW/`) | Yes |
| `i18n/` | Translation source (`i18n/src/`) and English TSV tables (`i18n/en/`) | Yes |
| `tests/` | Automated Node test harness and unit tests | Yes |
| `tools/` | CLI scripts for developers, CI, i18n, and maintenance | Yes |
| `.github/` | GitHub Actions CI workflows & issue templates | Yes |
| `data/` | Local SQLite database & uploaded photos | **No** (`.gitignore`) |
| `local/` | Private ops scripts, local notes, exports & one-time secrets | **No** (`.gitignore` & `.dockerignore`) |
| `seed_users.json` | Hashed starter accounts generated by `tools/make_seed.py` | **No** (`.gitignore`) |

> **Rule:** Never drop ad-hoc `.md` notes, `.csv`/`.html` exports, `.txt` password files, or helper scripts directly in the root directory.

## 2. Subdirectory Conventions

### `web/` — Frontend Application
- Core files: `index.html`, `style.css`, `polish.css`, `app.js`, `data.js`, `content.js`
- Feature modules: one focused JS file per major area (e.g. `guide.js`, `sim.js`, `arena3d.js`, `pathplan.js`, `control.js`, `taiwan.js`, `iqimport.js`, `modules.js`, `extras.js`, `about.js`)
- Third-party static bundles: `web/vendor/` (always document license & version in `docs/NOTICE.md`)
- Generated files: `web/i18n-en.js` (generated by `python3 tools/i18n_build.py`), `web/version.json` (generated by `python3 tools/build_info.py`, gitignored)

### `tools/` — Developer & Maintenance Scripts
All standalone CLI scripts live here:
- `tools/build_info.py` — generates `web/version.json` from `VERSION` and `CHANGELOG.md`
- `tools/make_seed.py` — generates `seed_users.json` and `local/secrets/初始帳密.txt`
- `tools/check.py` — pre-commit / CI checks (Simplified Chinese, forbidden files, secret patterns)
- `tools/i18n_extract.js`, `tools/i18n_todo.py`, `tools/i18n_build.py` — bilingual translation pipeline
- `tools/export_questions.js` — exports question review sheets into `local/exports/`

### `docs/` — Public Documentation
- English docs live directly in `docs/` (`CONTRIBUTING.md`, `ROADMAP.md`, `SECURITY.md`, `PROJECT_STRUCTURE.md`, etc.).
- Traditional Chinese (正體中文) docs live in `docs/zh-TW/`.
- **Never** commit private LAN IPs, NAS paths, or credentials to `docs/`.

### `local/` — Local-Only Workspace (Gitignored & Dockerignored)
All machine-specific or private files go under `local/` so they stay organized without polluting the root or entering Git/Docker:
- `local/ops/` — local deployment or DNS helper scripts (e.g. `.command` scripts; use `cd "$(dirname "$0")/../.."` to run from project root)
- `local/notes/` — private architecture drafts, ops logs, and scratch notes
- `local/exports/` — generated exports such as question review HTML/CSV
- `local/secrets/` — temporary credential files (delete once passwords are changed)

## 3. Rules for Future Development
1. **New frontend feature** → add to an existing module or create `web/<feature>.js`, register it in `web/index.html` and `tools/i18n_extract.js`, add translations in `i18n/en/`, and add tests in `tests/run.js`.
2. **New CLI / automation script** → place in `tools/` (if public) or `local/ops/` (if machine/NAS-specific).
3. **New public doc** → place in `docs/` (and mirror in `docs/zh-TW/` when user-facing).
4. **Docker safety** → `.dockerignore` must contain **pure ASCII rules only** (non-ASCII patterns break some NAS Docker builds).
5. **Before every commit** → run:
   ```bash
   for f in web/*.js; do node --check "$f"; done
   python3 -m py_compile server.py tools/build_info.py tools/make_seed.py tools/check.py
   node tests/run.js
   python3 tools/check.py
   ```
